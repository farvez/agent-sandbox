agent-sandbox

A containment layer for autonomous coding agents. The agent can read files, write files and run shell commands — and every command runs in a fresh, throwaway container that cannot reach the network and cannot outgrow its resource budget.

Isolation boundary

Where a command actually runs

Each boundary sits inside the one before it. Files survive between commands through the bind-mounted workspace; processes do not — every run_command gets a new container that is removed afterwards.

How it was built

Five steps, each runnable on its own

  1. 1RUNNER

    step1_runner/runner.py

    Host subprocess with shlex argv, hard timeout, stdout/stderr capture, 127 on missing binary.

  2. 2CONTAINER

    step2_container/container_runner.py

    One ephemeral container per command with network disabled, RAM+swap pinned to 256 MB so the OOM killer fires, CFS CPU quota, PID limit against fork bombs, OOMKilled inspection.

  3. 3TRACING

    step3_tracing/tracer.py

    Wraps the command in strace -f -c with SYS_PTRACE and parses per-syscall counts for file, process and network calls.

  4. 4GVISOR

    step4_gvisor/gvisor_runner.py

    Detects the runsc runtime via docker info and uses gVisor's user-space kernel; falls back to runc when it isn't registered.

  5. 5AGENT

    step5_agent/

    SandboxedWorkspace plus an OpenAI tool-calling agent that inspects, patches and re-runs tests until they pass. demo.py plants a broken Fibonacci and watches it heal.

Deployment · terraform/

One EC2 host, provisioned at boot

Terraform zips only src/, the Dockerfile and requirements into a private S3 bucket, generates one API key per tenant and stores them as an SSM SecureString, and launches Ubuntu 22.04 with an instance role that can read just those two things.

Docker CE→ gVisor (signed apt repo)→ code from S3→ build sandbox-base→ API as user “sandbox”, keys from SSM→ Caddy :443

No SSH: shell access goes through SSM Session Manager. IMDSv2 only, encrypted root volume, port 443 limited to allowed_ingress_cidrs.

MediumKeys are issued by redeployingapi/server.py · terraform/

Keys and limits are read from configuration at startup, so adding a tenant means terraform apply and a restart, and sessions and limits live in one process's memory. Next: keys hashed in a database with self-service issuing, and shared state for more than one API server.

FixedNo per-tenant session caps or rate limitsapi/limits.py

Per-tenant limits return 429: concurrent sessions (default 10), requests per minute (token bucket, default 120, with Retry-After) and concurrent commands (default 4). Configurable per tenant with "*" defaults; GET /v1/usage reports them. Live demo: grabbing every sandbox stops at 10.

FixedNo disk quota on /workspacestep5_agent/workspace_pool.py · terraform/

Workspaces are pre-made slots on a size-capped ext4 filesystem with project quotas (512 MB each, 15 GB total), so neither one session nor all of them can fill the server's disk. Verified under gVisor: a 4 GB write stops at 512 MB with Disk quota exceeded. Elsewhere the workspace warns and refuses API writes once over quota.

MediumEvals are a smoke test, not a benchmarkevals/

Iteration counts and timeouts are now real. The adversarial task still passes whatever the agent does, and each task runs once. Next: run each task several times (pass@k) and record whether the agent tried the exfiltration.

LowSmaller itemsvarious

A narrow race between the path check and the file open. GVisorExecutionResult.is_sandboxed is always true (the server now enforces gVisor separately). runner.py:37 operator precedence. Partial logs dropped on timeout. step2_container duplicates sandbox.py. In-memory sessions are lost on redeploy.

FixedOne shared API key: every caller was the same tenantapi/server.py · terraform/

SANDBOX_API_KEYS="acme:<key>,globex:<key>" maps each key to a tenant, and sessions belong to tenants. The key is checked in constant time against every configured key, without stopping early. Terraform generates a 48-character key per name in tenants. Tests cover the parser and cross-tenant 403s on read, write, exec and delete.

FixedWritable container root filesystemstep5_agent/sandbox.py

read_only=True with a 64 MB noexec tmpfs on /tmp and HOME=/tmp. Real-container tests check that writes to /etc fail and that /tmp fills up at its limit.

FixedAgent loop crashed on tool errors; output unboundedstep5_agent/agent.py

Any exception from a tool (blocked path, missing argument, Docker error) goes back to the model as the tool result. Output over 8,000 characters keeps its head and its tail, where errors and exit codes usually are. Tested with a scripted fake model.

FixedSymlink escape from the workspace to the hoststep5_agent/sandbox.py

Paths are resolved with realpath and must share the workspace root via commonpath. Tests cover links to host files and directories. On Docker Desktop for Windows, container-made links can't be followed by the host at all.

FixedDefault keys, open ingress, arbitrary imagesapi/server.py · terraform/

The server refuses to start without keys and compares in constant time. Terraform generates the keys, stores them in SSM, opens only 443 to your CIDRs, and has no SSH. Templates are allowlisted.

FixedTerraform could not plan, and would not have deployedterraform/user_data.sh

${ARCH} collided with templatefile. The code was never copied to the host, and the service was never started. The script now renders and passes bash -n. Code ships from S3, the service runs as a non-root user behind Caddy TLS, and gVisor comes from its signed apt repository and is required.

FixedOne running command froze the whole APIapi/server.py

Async endpoints were calling blocking Docker code. Endpoints are sync again (FastAPI's thread pool) with a thread lock. A regression test checks that /healthz answers while a slow exec runs.

FixedOOM kills were never reportedstep5_agent/sandbox.py

container.attrs was a snapshot from creation; container.reload() now runs before reading OOMKilled. Covered by a real-container test.

FixedContainer hardening, tracer bugs, session sweeper, missing testsvarious

cap_drop=ALL and no-new-privileges. Tracer quoting, exit code and column parsing, now unit-tested. The sweeper can no longer die silently. python-dotenv added. 157 tests across runner, paths, tracer, egress proxy, workspace pool, tenant limits, API, agent loop and real containers.
